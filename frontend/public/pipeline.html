GeoMate · Autocross Pipeline

Track Reconstruction
Pipeline

How raw dashcam footage becomes a measured 3-D autocross track — step by step, model by model.

Stage A
Frame Extraction
+ GPS Sync
ffmpeg · gpxpy
Two dashcam videos (NH1, NH2) are sampled at 6 fps. GPS coordinates from the GPX track are interpolated per frame and written as EXIF overrides into each image's metadata.
6 fps
~2,800 frames
2 video clips
→ images/ · exif_overrides.json · config.yaml
A
Raw dashcam frame — NH1_000667
Stage B
Structure from
Motion (SfM)
OpenSfM · HAHOG features · GPS priors
OpenSfM extracts keypoints from every frame, matches overlapping pairs, then incrementally reconstructs camera poses and a sparse 3-D point cloud. GPS priors anchor the scene to real-world coordinates. Undistortion and multi-view depth maps follow.
~1,262 shots registered
1.8 GB tracks.csv
2 recon components
→ reconstruction.json · undistorted/ · depthmaps/
B
Sparse reconstruction — camera positions + point cloud (top-down)
Stage C
Semantic
Segmentation
Mask2Former · Cityscapes-150
Every undistorted frame is passed through Mask2Former, a transformer-based panoptic segmentation model trained on Cityscapes. Each pixel is labelled: road, vegetation, person, vehicle, etc. Labels are saved as per-frame NPZ files.
→ labels_rec1/*.npz · *_vis.png overlays
C
Mask2Former output — grey=road · green=vegetation · blue=vehicle/person
Stage D
Labeled Point
Cloud Assembly
OpenSfM depth maps · semantic labels
For each frame, depth map pixels are back-projected into 3-D using the calibrated camera pose. The semantic label of each pixel is transferred to the resulting 3-D point. All frames are merged into a single labeled cloud stored in cloud.npz.
~6.8 M road pts
~66 K grass pts
~140 K cone pts
→ cloud.npz
D
Labeled cloud — top-down projection (road=dark, grass=light)
Stage E
Cone Detection
+ Clustering
YOLO-World · DBSCAN clustering
YOLO-World (open-vocabulary detection) finds traffic cones in every frame. Each 2-D detection box is back-projected onto the depth map to recover a 3-D position. Observations across all frames are clustered with DBSCAN; cluster centroids become the measured cone positions stamped into the cloud.
310 measured cones
≥2 obs threshold
0.75 m cluster radius
→ cone_detections.json · cones.json · cloud_with_cones.npz
E
Cone cluster centroids (orange dots) stamped into the labeled cloud
Stage F
Track Export
Grid-cell rasterization · JSON / OBJ
The labeled cloud is rasterized onto a 0.35 m grid. Each cell is classified as road, grass, or outside based on the dominant label of its constituent points and a configurable road-buffer margin. The result is exported as track.json (browser) and track.obj (mesh).
78,740 road cells
132,955 grass cells
0.35 m cell size
→ track.json · track.obj · track.mtl
F
Road cells colored by elevation (left) · road/grass class map (right)
Stage G
Diagnostics
matplotlib
Diagnostic plots are generated to verify reconstruction quality: top-down class map with cone overlays, z-elevation histogram by class, road height profile, and height cloud heat maps. Large z-spread indicates noisy depth maps.
→ diag/topdown_classes.png · z_hist.png · height_profile.png
G
Top-down class map — blue=road · green=grass · orange=cones
Stage H
Interactive
3-D Simulator
React · Three.js / R3F · Vite
track.json is served to a browser-based simulator. Road and grass cells render as merged BufferGeometry meshes. Cones render as instanced meshes at exact measured positions. A kinematic vehicle can drive the reconstructed track with surface-based grip and cone-hit detection.
WebGL renderer
60 fps target
cone editor built-in
→ frontend/ served at /
